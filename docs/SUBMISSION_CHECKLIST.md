# Submission Checklist

## HackQuest portal

- [ ] Team is registered before the displayed registration deadline.
- [ ] Authenticated portal timezone is recorded.
- [ ] Team size, eligibility, repository visibility, license, IP, KYC, travel, milestone, and pre-existing-code rules are verified from the current Terms and Conditions.
- [ ] Overall and Promising Products track opt-ins are confirmed.
- [ ] Required project, pitch, demo, and contact fields are complete.
- [ ] Submission is sent at least 24 hours before the displayed deadline.
- [ ] Confirmation page and email are captured.

## Product evidence

- [ ] Production URL works in a logged-out browser.
- [ ] Arbitrum Sepolia chain ID and Circle test USDC address are correct.
- [ ] Contracts are verified and match the submission commit.
- [ ] Commit, reveal, settle, claim, listing, and purchase transactions are linked.
- [ ] Two-wallet acceptance flow passes from the production interface.
- [ ] Test summary, invariant list, gas evidence, and Slither report are published.
- [ ] Known limitations and testnet disclaimer are visible.

## Repository

- [ ] README reflects deployed facts without placeholder claims.
- [ ] Setup instructions reproduce the local environment.
- [ ] `.env.example` contains placeholders only.
- [ ] Gitleaks and GitHub secret scanning report clean.
- [ ] License, security policy, architecture, auction spec, threat model, and demo runbook are current.
- [ ] No personal data, seed phrase, private key, authenticated RPC token, or production credential appears in history, issues, Actions logs, artifacts, screenshots, or video.

## Presentation

- [ ] Three-minute video permissions and audio are verified.
- [ ] Pitch numbers match contract fixtures and UI.
- [ ] Fallback video is available offline.
- [ ] Demo wallets are isolated testnet identities.
- [ ] No private browser tab, notification, API key, or wallet recovery material appears in the recording.
